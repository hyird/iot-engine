# 历史记录原始报文

## 统一的持久化结构

平台直采与边缘节点使用现有 `device_data` TimescaleDB 表，不新增一套协议专用历史表，不修改历史迁移。

- `data`：统一归一化的要素对象，包含数值、质量、采样时间等。
- `raw_payload_hex`：JSONB 数组；每个元素是一帧实际收到的完整原文，使用无空格的大写 HEX。
- `protocol`：`S7`、`Modbus` 或 `SL651`。
- `source`：保留实际采集来源。
- 时间继续使用 UTC `TIMESTAMPTZ`。

S7、Modbus 保持每个响应一条记录；一次响应包含多个要素时仍只生成一条记录。原文是单元素数组，例如 `["030000..."]`。节点原有采集和上报周期保持不变，并非将每秒内部读取都改为立即上报。

SL651 单包使用单元素数组；分包重组得到的完整业务记录使用按协议包序号排列的原始帧数组。保留帧头、结束符和 CRC，不把重组后的报文体重新编码成伪造的原始帧。重复分包不会重复加入数组。重发最后一包仍能获得协议确认。

仍遵循已有存储策略：`report` 按上报存储；`change` 只存要素变化的记录。调试期间的全部收发片段、无效帧和发送失败日志属于另一个功能，不由历史记录完整覆盖。

## 边缘上传协议

`TelemetryRecord.raw_payloads`（字段 14）统一承载原始帧数组。平台优先使用该数组；数组为空时兼容字段 10 `raw_payload`，转换成零个或一个数组元素。两个字段同时存在时不重复拼接。

新节点的 S7、Modbus 同时填写数组和旧字段，兼容旧平台。旧版 `0.3.44` 节点的报文继续接收；旧节点没有提供的原文不能补造，补齐实际原文上报需要升级节点固件。

SL651 大报文保持现有 16 KiB WebSocket 上限，以 `report_id`、`part_index`、`part_count` 表示一条逻辑记录的上传分块。每块拥有独立 `record_id`，沿用节点 outbox 的确认与重传。

- 节点每个分块的值或原文数据预算为 12 KiB 左右，为 Protobuf 元数据及 Envelope 留出空间。
- 单条逻辑记录最多 256 个上传分块。
- 平台单块记录上限 14,000 字节，累计编码数据上限 4 MiB。
- 原始 SL651 帧最多 4,095 帧，单帧最多 4,112 字节，原文总计最多 147,456 字节，覆盖现有 64 KiB 重组体及帧头开销。
- 数值分块与原文分块全部收齐后，合成一个 `ParsedDeviceMessage`，再进入现有归一化、幂等和历史写入链路。上传分块不直接成为历史记录。

## 分块持久化及失败恢复

Redis Hash `iot:edge:telemetry-upload:<node_id>:<device_id>:<report_id>` 保存原始 Protobuf 分块及共同元数据签名。实体映射位于 `features/edge/edge.entity.h`；动态序号字段及原子检查由所属 service 的 Lua 实现。

Lua 原子拒绝同序号内容冲突、共同元数据冲突及超过累计容量的写入。乱序分块按序号读取，重复分块不重复累计容量。节点、设备及逻辑记录共同限定存储身份，重连后的 Worker 可以继续处理。

未完成分块不设置 TTL：已经确认接收的原文不能因平台停机或节点长期离线而静默过期。缺块期间不生成部分历史记录；永久缺块的上传保留待恢复数据。这部分持久记录的运营清理不能按普通短期调试缓存处理。

完整记录成功进入现有持久消息队列后，才回收分块内容，并保留七天的完成回执。回执到期后的完整重放仍由 SL651 原始帧、设备及采样时间形成的业务身份和历史唯一性约束去重。

## 验证范围

- 节点主机测试覆盖 S7、Modbus 分响应原文、同一响应多个要素，以及 SL651 原始帧、乱序分包、图片、持久化前不确认和重复末包确认。
- 平台 C++ 测试覆盖数组优先级、字节及顺序保持、完整记录合并、缺块拒绝及设备隔离。
- `tests/edge-telemetry-upload-integration.ts` 在隔离 PostgreSQL、Redis 和 API 上验证真实 WebSocket 到历史表：三种协议的统一字段、分块中途重连、重复上传、缺块不入库，以及完成后的分块回收。
- 代码验证不表示已经生成或部署生产固件；历史页面的原文展示入口未包含在本次修改中。
