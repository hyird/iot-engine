# 设备与链路报文调试

## 开关与界面

- 设备与链路分别保存 `debug_enabled`，生效条件为两者逻辑或；需手动关闭，关闭窗口不关闭调试。
- 卡片使用图标按钮；调试生效时才显示报文入口。窗口默认最大宽 1440px、高 92dvh，保留右下角调整尺寸。
- 设备窗口使用终端式采集树：整轮为根节点，按明确的 `reply_to_packet_id` 组织请求、响应和 ACK，解析结果每轮只显示一次。各协议展示自己的报文字段；未识别或不完整帧保留原文。
- 链路窗口使用连续收发日志，跨轮次按报文时间排列，不显示采集树或历史解析结果。两种视图均无表格、分页和来源列，时间统一为 `YYYY-MM-DD HH:mm:ss.SSS`。
- 默认跟随底部，向上滚动、选取文本或操作采集树时暂停跟随；可一键回到底部。设备树默认展开，支持单轮和全部折叠。报文可完整选择及复制，长原文自动换行；虚拟列表按稳定 ID 保留状态。
- 两个页面通过 SSE 获取轮次快照；窗口关闭取消订阅。报文使用稳定 ID，发送状态、协议应答和历史入库分别更新。

## 统一身份与粒度

所有协议、平台直采和边缘节点统一使用采集轮次身份：主动轮询的一整轮读取是一个轮次；SL651 一次完整业务上报（含分包）是一个轮次；手动命令的请求与读回使用命令身份。轮次中保留独立报文身份及 `reply_to_packet_id`，不按 HEX、流水号相近或接收时间猜测分组。

平台协议会话使用运行层提供的连接身份和会话内轮次序号计算轮次 UUID。边缘节点在实际读取前创建轮次 UUID，所有请求、响应、结束事件及后续历史上报沿用该身份。SL651 会话保留重发与分包关联。历史消费者沿用轮次 ID，不再按内容重新生成历史 ID。

采集状态为 `running`、`success`、`partial`、`failed`。没有响应的失败轮次仍能显示；失败轮次不作为完整历史保存。历史状态独立表示待入库、已入库、未保存或入库失败。成功采集不保证触发历史上报或符合保存策略。

发送队列完成 socket 写入后确认；队列 ACK 不等于设备应答。应答状态由协议校验与超时结果更新。数据库提交成功后才更新历史关联，迟到的中间状态不能覆盖终态。

## Redis 模型

- `iot:debug:v3:acquisition:<id>`：轮次 Hash，保存开始/结束时间、采集状态、设备/链路、历史 ID、解析结果和保存状态。
- `<轮次 Hash>:packets`：按首次捕获时间排序的报文 ID 集合。
- `iot:debug:v3:packet:<id>`：唯一报文 Hash，保存原文、方向、时间、请求关联及状态。传输分块按偏移保存在同一 Hash，合成为一条完整原文；偏移不再成为显示行身份。
- `iot:debug:v3:device:<id>`、`iot:debug:v3:link:<id>`：轮次索引，共享同一份轮次与报文。

Lua 原子维护身份约束、状态推进、索引和回收。每个视图最多保留 100 个轮次，每轮最多 4096 个报文，快照最多返回 4096 个报文且不截断轮次。整个轮次及其报文以首次创建时间为基准保留 24 小时，重试不延长寿命。超过数量限制时整轮清理；仅在两个索引均不再引用时提前删除内容。回收标记阻止迟到消息重新创建刚清理的轮次。

实体映射位于 `features/packet_log/packet_log.entity.h`，跨 Hash/ZSET 的原子事务由所属 service 的 Lua 完成，原因是公开 ORM 不支持该跨键事务。

## 边缘契约与交付

`RawPacket.acquisition_id`（字段 14）标识轮次，`acquisition_state`（字段 15）承载轮次开始/结束事件；生命周期事件无原文，不成为报文行。历史记录使用 `raw_payloads` 与 `raw_packet_ids` 数组；旧单值 `raw_payload` 已删除并保留其字段编号，避免误用。

平台校验已认证节点、链路、设备归属及当前调试开关。调试为在线尽力上报，不进入历史补传队列；离线或背压可能缺失调试内容。历史上传继续使用可靠分块、确认与重传。

本次为不兼容的调试与历史上报契约变更：平台、前端和采集固件需作为同一发布批次验证。旧调试缓存不读取、不迁移，可按原 TTL 清理；切换时应先排空在途历史消息并备份，生产历史业务记录不删除、不改写。数据库历史表及调试开关迁移保持不变。

## 验证

- `packet-debug-storage-integration.ts`：真实 Redis 的身份、重放、状态、分块、空轮次和整轮回收。
- `packet-debug-collector-integration.ts`：平台 Modbus 双段读取、整轮历史、独立开关、异常应答与超时。
- `collector-publication-integration.ts`：SL651 报文状态更新、ACK 关联及队列失败后重试。
- `edge-telemetry-upload-integration.ts`：六种协议的边缘上报、分块重连、整轮入库和无重复状态更新。
- `packet-debug-test.ts`：重叠时间与相同原文仍保持轮次独立，空失败轮次保留。
