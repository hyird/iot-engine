# 设备与链路报文调试

## 入口与开关

- 设备页面的设备卡片提供开启／关闭调试和报文入口，只管理该设备的独立开关。
- 链路页面的链路操作区提供相同入口，管理该链路及其下设备的调试。
- 生效条件为 `link.debug_enabled || device.debug_enabled`。两者分别保存，互不修改。
- 设备独立开关关闭、链路开关开启时，设备显示“链路调试中”。两个开关都关闭才停止该设备调试。
- 开关需手动关闭，关闭报文窗口不会关闭调试，平台重启保留开关。
- 入口使用图标按钮和悬浮提示；只有设备独立调试或链路调试生效时才显示报文窗口按钮。
- 调试窗口默认最大宽 1440px、高 92dvh，可拖动右下角调整尺寸，表头和操作区固定、报文列表内部滚动。

## 状态、历史与实时更新

设备和链路报文窗口均使用现有 SSE 订阅，关闭窗口后取消订阅。发送方向统一显示“发送”，状态独立显示发送中、等待应答、已发送、应答成功或失败，失败原因可以悬浮查看。同一事件 ID 的状态更新通过 Lua 原子更新共享 Redis Hash，Redis 和页面均只保留一条最新状态，迟到的中间状态不会覆盖终态。

发送队列在实际 socket 写入完成后确认；队列 ACK 不等于设备应答。S7、Modbus 使用协议解析器的请求匹配与校验结果更新应答状态；设备返回异常或请求超时显示失败。SL651 无需再次应答的协议确认报文写出后显示“已发送”，远程命令以其协议结果完成状态。

历史消费者完成数据库提交后，按该次消息 ID 确认历史记录实际存在，再发布带历史 ID 和数据库解析数据的完整原文记录。平台直采完整帧在接收时分配独立的 raw_packet_ids，经遥测队列传递到历史消费者；入库完成后沿用对应报文 ID 更新为“已入库”，不再新增一行。该身份不随 SL651 历史幂等归一化改变，也不使用流水号或时间相近推测关联。非完整网络分片仍单独保留。因存储策略没有入库的样本不伪装成历史记录。调试显示失败不影响历史持久化的队列确认。

调试时间显示到毫秒。设备历史表最右侧为原始报文列：悬浮展示全部原文数组，点击复制完整 JSON 数组；旧记录没有原文时显示“—”。接口字段为 `rawPayloadHex`。

## 存储

迁移 `0048_packet_debug_switches` 分别在 `device`、`link` 增加 `debug_enabled BOOLEAN NOT NULL DEFAULT FALSE`。开关变更通过配置消息下发。

调试内容使用 `iot:debug:v2:packet:<packet-id>:<offset>` Hash，设备和链路分别使用 `iot:debug:v2:device:<id>`、`iot:debug:v2:link:<id>` Sorted Set 索引；两个索引共享一份内容。Lua 原子更新状态、revision、双索引和引用清理；拒绝同身份的归属、方向及原文冲突。每个索引最多 500 项，每块最多 4096 字节；内容自首次创建保留 24 小时，更新不延长寿命、不改变排序。索引有 TTL，读取清理失效引用。仅在两个索引均不再引用时提前回收内容。迟到的历史状态不会复活已过期记录。

历史采集记录仍独立写入 PostgreSQL/TimescaleDB，原文保存在 `raw_payload_hex` JSONB 数组。调试关闭不影响历史采集及原文保存；所有协议均按一次完整采集或完整上报保存一条历史记录，原文和报文身份使用数组。详见 [历史原文说明](history-raw-payloads.md)。

## 平台与边缘节点

平台直采直接在所属 Collector Worker 捕获收发，调试开关变化不重建采集连接。平台发送方向标记为 `TX`，状态区分写入与协议应答；接收允许包含传输层分片，不能将每条调试记录都理解为完整协议帧。

边缘节点接收相同配置字段，捕获实际发送和接收字节后，通过现有 WebSocket 上报统一 `RawPacket`。平台按已认证节点、链路和设备归属校验，并再次检查当前开关后保存。边缘调试为在线尽力上报，不进入历史补传队列；离线或背压时可能缺失调试报文。

SL651 链路视图保留原始接收片段；设备视图使用能识别所属设备的完整候选帧。无法可靠归属设备的报文仅进入已开启调试的链路视图，避免串入其他设备。

旧固件 `0.3.44` 的既有协议路径保留，但新增调试采集需要升级支持该功能的固件。边缘节点当前沿用完整配置应用流程，开关变更可能短暂重建南向采集连接。

## 统一采集粒度

Modbus、S7 按整轮读取，SL651 按完整业务上报合并解析值，原文与 raw_packet_ids 按顺序保存为数组。调试保留每次实际收发，多个响应可以关联同一个历史 ID。失败轮次不作为完整历史保存，也不混入下一轮。

新固件通过 TelemetryRecord 字段 18 上传原文身份，RawPacket 字段 12、13 分别携带偏移和回复目标。平台为边缘身份增加节点命名空间。旧固件缺少身份时不猜测历史关联。旧版 Redis Stream 不参与新结构读取，也不按 HEX 或时间迁移，可等待原 TTL 清理。

状态分别使用 transport_status、response_status、parse_status、storage_status；队列确认、设备应答和数据库提交是不同状态。SSE 以稳定 ID 更新快照，前端按 revision 保留同一行较新的状态。源码验证不代表已部署，平台必须先于新固件升级。
