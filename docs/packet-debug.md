# 设备与链路报文调试

## 入口与开关

- 设备页面的设备卡片提供开启／关闭调试和报文入口，只管理该设备的独立开关。
- 链路页面的链路操作区提供相同入口，管理该链路及其下设备的调试。
- 生效条件为 `link.debug_enabled || device.debug_enabled`。两者分别保存，互不修改。
- 设备独立开关关闭、链路开关开启时，设备显示“链路调试中”。两个开关都关闭才停止该设备调试。
- 开关需手动关闭，关闭报文窗口不会关闭调试，平台重启保留开关。

## 存储

迁移 `0048_packet_debug_switches` 分别在 `device`、`link` 增加 `debug_enabled BOOLEAN NOT NULL DEFAULT FALSE`。开关变更通过配置消息下发。

调试报文使用 Redis Stream：`iot:debug:packets:link:<id>` 和 `iot:debug:packets:device:<id>`。统一字段包括链路、设备、方向、来源、地址、HEX 原文、毫秒时间和分块偏移。每个列表最多 500 条，每块最多 4096 字节；最后一次写入后 24 小时清理列表，此期限不影响调试开关。

历史采集记录仍独立写入 PostgreSQL/TimescaleDB，原文保存在 `raw_payload_hex` JSONB 数组。调试关闭不影响历史采集及原文保存；S7、Modbus 仍保持每次有效响应一条历史记录。详见 [历史原文说明](history-raw-payloads.md)。

## 平台与边缘节点

平台直采直接在所属 Collector Worker 捕获收发，调试开关变化不重建采集连接。平台发送方向标记为 `TX_ATTEMPT`，表示尝试发送；接收允许包含传输层分片，不能将每条调试记录都理解为完整协议帧。

边缘节点接收相同配置字段，捕获实际发送和接收字节后，通过现有 WebSocket 上报统一 `RawPacket`。平台按已认证节点、链路和设备归属校验，并再次检查当前开关后保存。边缘调试为在线尽力上报，不进入历史补传队列；离线或背压时可能缺失调试报文。

SL651 链路视图保留原始接收片段；设备视图使用能识别所属设备的完整候选帧。无法可靠归属设备的报文仅进入已开启调试的链路视图，避免串入其他设备。

旧固件 `0.3.44` 的既有协议路径保留，但新增调试采集需要升级支持该功能的固件。边缘节点当前沿用完整配置应用流程，开关变更可能短暂重建南向采集连接。
