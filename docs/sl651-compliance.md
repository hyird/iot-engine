## 本次实现

实现对象包括平台 Collector 和 EdgeNode 0.3.45 的 HEX/BCD 会话。`responseMode` 从协议配置经数据库快照、Redis 快照传递到连接所属 Worker；边缘设备通过增量 protobuf 字段 `DeviceConfig.sl651_response_mode` 下发，0 保持旧配置的 M1 默认值。

| 模式 | 接收及确认行为 | 标准依据 |
| --- | --- | --- |
| M1 发送/无回答 | 单帧 STX/ETX；不发送确认，拒绝平台下行命令 | 6.3.1.2 a）、图 1 a） |
| M2 发送/确认 | ETB 后 ACK，最终 ETX 后 EOT；确认复制站址、中心站、密码、功能码及上行流水号 | 6.3.1.2 b）、图 1 b） |
| M3 多包发送/确认 | SYN，12 位总包数及包序号；乱序重组、重复包识别、逐包 NAK 补传；完整报文后确认，最终确认使用总包数对应的序号 | 6.3.1.2 c）、图 1 c）、图 2 a）、6.6.2 |
| M4 查询/响应 | 中心 ENQ；收到匹配的 ETB 后 ACK 并继续等待，最终 ETX 后 EOT 并完成命令 | 6.3.1.2 d）、图 2 b） |

按图 1 b）、图 2 b） 处理连续响应中的 ACK 与最终 EOT。查询超时保持原发送字节重试两次；M3 每个缺失序号最多请求两次。M3 组包进行中由组包定时器负责补传，查询定时器不重复下发查询。

按 6.6.2.4，中心主动报文流水号为 0，上行流水号为 1–65535，确认复制上行流水号。查询关联使用当前连接、站址、中心站、密码及功能码，并识别已确认响应。`E0`–`FF` 保持用户扩展语义，`E1`、`E2` 不作为通用成功或失败回执。超时后同一连接中的该设备停止接受新查询，重新连接后恢复，避免无法区分的旧响应误完成新命令。

确认晚于解析消息写入 Redis 接入流成功，后续由现有遥测消费流程持久化。这里的确认边界是 Redis 持久化队列接入，并非遥测数据库写入完成。部署依赖已有 Redis AOF 配置。最终命令结果先持久化再发 EOT；持久化失败时保留可重试状态，重复最终响应只重放原命令结果。

## 自定义要素

不建立固定要素或功能码白名单。用户可自定义名称、引导符、单位、字典及编码解释，但必须满足 6.6.3 的报文结构：

- 普通数值要素使用两字节引导符，`FF` 扩展使用三字节；数据定义高 5 位表示字节数，低 3 位表示小数位数。
- 示例 `AB12` 表示自定义标识 `AB`、2 字节、2 位小数；`FFB028` 表示扩展标识 `B0`、5 字节、0 位小数。
- 负 BCD 以 `FF` 表示负号，符号计入配置长度。例如 `FF1234`、长度 3、小数 2 表示 `-12.34`。
- `F0F0` 时间长度 5，`F1F1` 站址及分类长度 6；`F2F2`、`F3F3` 变长内容消费剩余正文。其他专用标识按配置长度解释。
- 解码从流水号和发报时间后的要素边界开始，跳过未配置的定长数值要素。不会搜索其他要素的载荷来伪造匹配；遇到未知且无法确定长度的专用要素则停止扫描，原始报文仍保留。
- 新增、修改配置均校验引导符与长度、小数位的一致性。既有不符合数据定义的配置需要修正，不再通过错误长度读取数值。

## 运行限制与验收边界

### 固定位置要素

普通要素与 `responseElements` 均支持 `positionMode: "GUIDE" | "OFFSET"`，默认 GUIDE。
OFFSET 不要求 `guideHex`，但必须配置正长度；`byteOffset` 为重组后完整正文的零基字节偏移。
偏移 0 指向流水号首字节，偏移 8 跳过两字节流水号与六字节发报时间，不包含帧头、SYN 分包序号、结束符或 CRC。
例如 `positionMode: "OFFSET", byteOffset: 8, length: 2, digits: 2, encode: "BCD", guideHex: ""`
读取正文第 8、9 字节。帧被分包时先重组，再定位。

混合布局先使用固定字段区，再使用引导符区；后者从同功能码、同应答类型的固定字段最大结束位置开始扫描。
下行固定字段不能覆盖正文 0–7，不能相互重叠，空隙填 0。固定位置是字段定位机制，不能据此省略标准规定必需的引导符；具体布局仍须符合所选业务报文或双方约定的扩展定义。

配置页面、API 校验、数据库/Redis 快照及边缘 protobuf 转换都保留定位方式与偏移。
`responseElements` 定义查询应答的数据解析，M2 的 ACK/EOT 由会话状态自动生成，不在应答要素里配置。

### 边缘节点

EdgeNode 支持 SL651 串口、TCP Client 和 TCP Server。一个物理连接只读取一次，各平台独立解析与入队；同一测站只发送一份确认，共享模式必须一致。
被动 SL651 串口不能与轮询协议或不同串口参数混用。只有各平台对应的记录都写入本地 outbox 后才确认；最终查询还等待命令结果入队。
IPC 发送成功不等于 outbox 成功，失败时用同一记录 ID 重试；已确认报文重传只重发确认，不重复发布。
连续应答等待超时重发上一条 ACK，初始查询重发 ENQ，各最多两次；M3 下行 ENQ 使用表 23 的 SYN 总包数/序号 1/1。

节点沿用 tmpfs outbox，支持进程重启恢复，不保证断电持久性，空间不足时仍按既有策略淘汰旧记录。
节点每帧正文最多 4095 字节，重组正文最多 64 KiB、4095 包；单个 HEX/DICT/JPEG 二进制要素最多 8 KiB，单次二进制总量最多 64 KiB，最多 128 个出站记录。超限不截断、不发送成功确认。
二进制字段以新增 `TelemetryValue.encoded_value`、`encoding` 传送，平台还原 HEX/DICT 文本或 JPEG data URL。原有标量字段、协议版本 6、0.3.44 的升级和下载路径保持兼容；旧固件本身不会因此获得新的 SL651 采集能力，需要升级节点程序。

本次不宣称完成整个标准的全部传输方式及全部业务命令语义：ASCII 编码未实现；非纯 BCD 站址形式未实现；每帧正文沿用 12 位长度、最大 4095 字节；每连接组包正文累计最多 8 MiB，组包空闲补传间隔为 30 秒。变长图片通过分包承载，最多 4095 包。超限中止组包。

缺首包时，中心还不知道上行流水号，NAK 使用 0；收到首包后使用真实流水号。这一边界需与实际设备核对。专用要素的业务语义、ASCII、非 BCD 地址及标准附录中的全部交互仍需要单独扩展与验证。

自动化测试覆盖模式差异、入队前不确认、ETB/ETX、CRC 和结束符拒绝、自定义要素边界、粘包逐条确认、乱序分包与缺包 NAK、重复响应、查询两次重试、超时隔离、负数 BCD、真实水文报文及图片重组。尚未完成实际测站互通、故障注入下的 Redis/数据库端到端验证及平台 Linux 构建。本次未部署、未刷写设备。
