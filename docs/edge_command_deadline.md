# EdgeNode 命令启动截止时间：迁移与验收

## 合同与边界

- `command_attempt.deadline` 是 PostgreSQL 持久化的**执行启动截止时间**。平台将其向下取整为 Unix 毫秒，经 `CommandRequest.start_before_ms = 8` 发送；不能从节点收到命令的时刻重新计算。
- `CommandRequest.timeout_ms = 5000` 仍表示设备响应等待时间，不是启动截止时间或队列生存期。节点在首次南向写入前检查截止时间、数据库时间映射有效期及失效代次；一旦任何字节可能已发出，不因随后过期而中断或重发该写入。
- 新节点通过 `Hello.supports_command_start_before = 36` 声明能力。平台仅对声明能力的连接提供同一 PostgreSQL 数据库的 `clock_timestamp()` 样本（`HelloAck.database_time_ms = 7`，及回显 `Heartbeat.nonce = 26` 的 `HeartbeatAck.nonce = 6` / `database_time_ms = 7`）。原有 `platform_time_ms` 保留，但不得用于命令截止时间换算。
- 节点按单调时钟测量样本往返：RTT 超过 2 秒、映射年龄达到 330 秒、样本缺失、nonce 不匹配或观察到不一致的数据库时钟时，拒绝尚未启动的命令。换算只在数据库时钟于样本间稳定、相对单调时钟的速率误差不超过 1000 ppm 的前提下建立保守上界；**未观察到的数据库时钟突变、线程停顿到 `write()` 调用之间的竞态以及设备实际接收时刻，都不能由协议严格保证**。不能向用户承诺无条件的物理执行截止时间。
- 写入未发送且已过期：`REJECTED`；写入可能已发送但缺少 ACK：`UNKNOWN`，不得自动重试；写入已获 ACK 而回读失败：`UNKNOWN`，提醒核对设备状态；回读值不匹配：`READBACK_MISMATCH`。迟到且已验证的成功可将 `UNKNOWN` 更新为 `SUCCEEDED`，不确定的迟到结果不得把它改为确定失败。

## 兼容顺序与回退

1. **先升级平台，后升级节点。**平台对未声明该能力的已部署 0.3.44/0.3.63 节点继续使用旧字段和旧命令协议；不能宣称这些旧节点获得了新的截止时间保护。
2. 升级单台新节点前确认平台已能提供数据库时间样本与持久化的截止时间，并在隔离环境验证管理端命令、nonce、断线及结果投影。新节点连接旧平台或无法得到可信样本时会拒绝管理端设备写入；这不是可静默回退的写入路径。应预先安排兼容窗口并告知运维，不要让节点以本地墙钟或接收时 TTL 代替缺失的字段。
3. 节点升级任务只能经认证管理流程创建。页面超时不表示任务未创建，先查询任务状态，切勿重复提交；无明确授权不得闪机或部署。保留配置与升级前镜像，若出现回归，按已核验的管理流程安排人工恢复，不假设自动回滚。
4. 只在平台与单节点验证通过后，逐步推广。兼容窗口内保持旧固件的 WebSocket 分块升级路径和 0.3.44 令牌下载路径，不擅自删除旧协议字段或历史任务记录。

## 验证门槛

- 固件：host 构建与全量 CTest、nanopb 0.4.9.1 重生成核对、两份 proto 字节一致；在正式构建机依次提交并推送源码、从干净发布检出 `git pull --ff-only`、完整构建 IT692/IT694、核对镜像哈希及根文件系统。主机测试并不等于目标设备或 WebSocket 全链路验证。
- 平台：Release 构建、CTest、前端类型检查/lint/生产构建和修改文件格式检查；隔离 PostgreSQL/Redis/API 集成测试验证原始截止时间、单次发送认领、旧节点报文、命令结果 `UNKNOWN` 及迟到成功。隔离测试使用模拟节点，不代表真实 PLC 行为。
- 获得单节点试验授权后，按实际读写与网络记录验证：离线队列恢复、串口静默、过期零次发送、部分发送后无重放、心跳重叠、SL651 连续应答 ACK 重试，以及整轮读完至下一轮约一秒。不能为复现故障对生产 PLC、其他节点或 VPN/防火墙施加写操作。
