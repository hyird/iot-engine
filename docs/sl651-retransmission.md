# SL651 定时报与加报的补发处理

## 采样与传输

标准单包定时报（`0x32`）、加报（`0x33`）的正文包含流水号、发报时间、`F1F1` 测站地址及分类、`F0F0` 观测时间。

- `observedAtMs`、历史 `report_time` 和指标 `sample_time_ms` 使用观测时间，按设备时区转换为 UTC。
- `occurredAtMs` 保留接收时间；每次传输的发报时间、流水号及校验码保留在原始报文中。
- 采样身份由链路、设备、功能码、流水号和观测正文确定；排除发报时间、接收时间和连接身份。
- 同一报文在重连或进程重启后补发，仍使用同一个采样身份。流水号循环后，只要观测时间或正文不同，仍保留为不同采样。
- 同一观测时间的修正值保留为另一条记录，不覆盖已有证据。

仅在明确识别并验证标准观测时间时使用该规则。缺少标准观测头的自定义正文、命令响应和多包组装继续使用各自的现有身份规则，不能从任意载荷中搜索 `F0F0`，也不能将多观测时刻的历史批量报文简单当作一个观测点。

## 确认和收发记录

收到合法补发后仍向持久化消息流发布。Redis 发布失败不发送确认；发布成功后每次都用该报文的流水号应答。此处的可靠接收边界是 Redis 消息流，不是 PostgreSQL 历史投影完成。

Redis fanout 按采样身份限制重复事件，PostgreSQL 的 `(id, report_time)` 唯一键防止回执过期后重复入库。每次 RX/TX 的独立报文身份不变，收发记录归属同一采样；每个 ACK 引用对应 RX。调试记录仍遵循既有保留期限和容量限制。

## 2026-09-17 排查证据

站号 `0001000102` 的三次接收分别为北京时间 `02:10:19.382`、`02:10:19.472`、`02:15:02.779`，流水号均为 `0x0076`，观测时间均为 `02:10`。发报时间分别为 `02:10:00`、`02:10:05`、`02:15:01`。新采样 `02:15` 使用 `0x0077`。

这些证据确认了重传和延迟到达；当时的 ACK 调试记录已超出当前保留范围，不能据此断定平台未应答或设备未收到应答。

## 验证与上线边界

协议测试使用上述三条真实报文验证跨会话身份、观测时间及持久化前不确认。TCP 集成测试验证实际 ACK、重连、Redis 回执删除后的数据库唯一性、不同观测时间、修正值及每次收发记录。

修复仅影响之后接收的报文，不自动重写已有历史。上线前应单独制定历史修复范围：

1. 按设备和时间窗生成只读预览，校验 CRC、流水号、观测时间和完整正文，列出需要归时或合并的记录。
2. 备份完整受影响行及其原始报文，确定保留的首次接收记录，保留所有重传证据；关联指标、告警及外部投递不得因修复再次触发。
3. 在测试库验证事务、重复执行与回滚，再执行生产修复。不能仅按流水号或指标数值删除历史。
4. 新版本不与旧版本并行采集同一设备，避免新旧身份规则在切换期间各写一条。发布仍须同一提交的 Linux、Windows 构建测试及同版本静态资源通过。
