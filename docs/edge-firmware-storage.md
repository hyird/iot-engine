# 边缘节点固件存储

## 上传与复用

管理页面先在浏览器计算文件 SHA-256，再调用 `POST /v1/edge/:id/firmware/reuse`，参数为 `sha256`、`sizeBytes`、`keepSettings`。服务端校验固件操作权限和节点升级能力，只有摘要、长度匹配且文件实际存在时，才创建升级任务并返回 `reused: true`。文件改名不影响复用。

未命中时，页面沿用 `POST /v1/edge/:id/firmware` 原始二进制上传及进度展示。服务端再次按摘要和长度去重；并发上传同一内容只保留一份文件和一条固件记录，各次升级任务分别保留。响应不确定时不自动重试上传或下发，避免重复操作。

固件记录和对应升级任务在同一数据库事务中写入。上传、复用与后台回收使用相同的事务级 advisory lock，避免回收与新增引用竞态；各 Worker 使用自己的数据库连接，无跨 Worker 内存共享。

## 一小时保留期

- 固件创建满一小时，且全部关联升级任务均已成功或失败满一小时后，删除固件记录与文件。升级任务历史保留。
- 任一未完成任务，包括断点续传中的任务，继续保护文件；复用会创建新的任务，保留期随最后完成的关联任务延后。
- 后台每分钟检查一次，每次最多回收 32 条过期记录和 32 个孤立文件，实际回收可能比保留期稍晚。
- 中断提交留下的孤立文件，只有位于配置目录、文件名为 UUID、扩展名为 `.bin`、无数据库引用且修改时间超过一小时的普通文件才回收。
- 比较文件引用前统一转换为绝对路径，保留使用相对路径的历史记录所引用的活动文件。
- `.upload` 临时文件仍由现有上传锁及启动恢复机制管理，不按文件年龄删除；非托管文件名和符号链接不删除。
- 固件回收后，再次升级需要重新上传该内容。

`EDGE_FIRMWARE_DIR` 仍为唯一固件目录配置，默认 `firmware`。已有任务与文件不需要数据库迁移。已部署 `0.3.44` 的令牌下载地址和支持分块固件的专用 WS 协议保持兼容。

## 行为验证

`tests/edge-firmware-integration.ts` 经 `tests/Run-SystemOrmIntegration.ps1 -TestFiles edge-firmware-integration.ts` 在隔离 PostgreSQL、Redis 和两个 Service Worker 上运行，覆盖：摘要命中与未命中、并发上传去重、缺失文件重新上传、旧版令牌下载、WS 分块与重复偏移续传、过期清理、未完成及近期完成任务保护、孤立文件清理、上传临时文件保留。使用模拟节点，不刷写真实设备。

`tests/firmware-upload-test.ts` 验证页面上传前的摘要请求、命中后省略文件请求、进度和设置参数，以及响应丢失时不自动重复下发。
