- 没有部署、重启、修改生产配置或安装软件；采样进程已自动退出，服务 PID 未改变。

## 本地优化与兼容边界

这些是本地修改，不是上述生产环境已经运行的效果：

1. 新建/缺失的读取上报间隔统一为 300 秒；显式配置、快速读取和历史迁移保持不变。
2. 新固件关闭 libuwsc 周期 WS Ping，由 300 秒应用心跳负责保活；平台 Ruvia 仅在连接空闲时触发 WS 探活，不改变响应对端 Ping 的行为。新固件应用看门狗上限为 900 秒，服务端会话租约 930 秒并同步过期索引。
3. Hello 增加可选 `supports_sparse_heartbeat = 35`，声明支持 300 秒探活及至少 900 秒应用看门狗。缺失字段保留旧时序，不能对 0.3.44 直接停掉必要保活。字段编号、协议版本及旧固件升级通道不变。
4. 新固件正常应用心跳计时器运行时不再另发应用 Ping；新服务端只检查超时，不向声明新能力的节点主动发送应用 Ping；收到节点心跳才确认。
5. 连续连接失败指数退避，从配置的初始间隔逐步延长到 300 秒；配置本身大于 300 秒时不缩短。稳定应用通信 300 秒后才复位；重复关闭通知不重复延长等待。
6. 收到待审批结果后按 300 秒心跳等待，不再被 30 秒初始握手看门狗反复断开；重连清理旧会话 epoch。
7. 新能力节点的遥测不再触发平台额外状态请求；旧固件仍保留必要状态请求，但重复遥测 ACK 和派生值更新不触发无关的全设备状态请求。原始报文、采样、必要确认和既有重放语义保留。
8. WG 生成配置和节点 UCI 保活改为用户选择的 120 秒。不改 WG 内部握手/重密钥协议；已有设备需明确应用新配置才会生效。现场仍需测试移动 NAT 空闲入站可达性。
9. 旧 nanopb `TelemetryAck.accepted_record_ids` 容量只有 1；未合批 ACK，未更改 Protobuf 压缩格式。

## 全链路通信审查

| 通信类别 | 保留或简化策略 | 当前结论 |
| --- | --- | --- |
| 应用心跳 | 节点每 300 秒主动发送，平台仅确认；新能力会话不主动 Ping | 本地已修改，旧固件保留兼容时序 |
| 遥测与原始报文 | 遵守配置周期；保留原始帧、采样及成功持久化后的单记录 ACK | 本轮未删减数据；超时只补发相关记录，原连接最多重试两次，耗尽再恢复连接；写缓冲限制 64 KiB 后暂停继续填充 |
| 设备状态 | 新能力节点不因遥测被平台反复请求状态；按 Protobuf 内容去重 | 首次连接、明确补报仍发送；遥测更新状态时清除独立状态缓存，防止交错更新被错误抑制 |
| 能力与网络状态 | 同会话相同内容不再重复发送；重连清空缓存 | 每会话首次配置后保留一次兼容补报，后续配置与网络确认只报变化 |
| 配置下发 | 实际变更触发；相同活动版本、摘要重放仅补 ACK | 不重复应用或重启采集；同版本摘要冲突拒绝，新版本仍完整验证 |
| 日志 | 明确请求后返回快照；新固件默认 `silent`，临时开启 300 秒后自动静默 | 本地已修改；单调时钟、本地执行、采集子进程共享期限，随已有心跳上报级别。旧固件仍须升级，未在生产验证 |
| 串口与终端 | 仅活动会话传输，关闭时清理，保留顺序、背压及续租 | 续租不是可直接删除的重复消息；不改变实时体验。采集报文抓取另由持久化的 `debug_enabled` 控制，不能声称已实现按浏览器订阅自动关闭 |
| DTU | 第三方透传原样保留，纯状态按实际内容去重 | 字节计数改变仍实时上报；带 trace 的消息不参加去重，不牺牲调试交付 |
| 固件升级 | 只有 offset 真正推进才立即请求下一块 | 重复/跳号块按已有重试期限拉取，避免连续重复请求；状态文件读后删除，不把 500ms 本地计时器误判为周期网络上传 |
| 网络配置确认 | 保留配置后主动探测与确认 | 这是操作相关的回滚安全验证，不是常驻心跳，不能删除 |
| 重连 | 有界指数退避，待审批不反复重新握手 | 本地已修改；不清空未确认队列来省流量 |
| WG | 按用户选择改为 120 秒 | 仅修改生成配置；协议自身握手不改，活跃隧道需实测 |

快照去重只用于可替换状态，不用于业务记录、事件或命令结果；分配/编码失败不缓存为已发送，下一次仍可补报。“全部通信纳入审查”不等于所有类型都已经完成优化或验收。未改变第三方设备协议、HTTP API、网页 SSE 或既有命令确认契约；涉及原始数据、调试交付、旧固件兼容的变更须分别验证。

## 0.3.50 平台连接区间流量统计

- 替换未发布的 WS 载荷估算，使用 Linux conntrack 的原方向、回复方向 IP 字节计数，分别上报上行、下行；包含内核所计 TCP/IP 包头、ACK、握手和重传。不是 SIM 账单统计，不包含其他业务、链路层或隧道外层开销；分片及网络卸载条件下的线速字节精度仍须实测。
- 仅登记各平台真实 socket 的完整 TCP 地址、端口元组；每个平台独立累计、独立确认，旧连接销毁事件的尾部字节仍归原平台。未发布的 WS 消息数及进程总量字段已移除。
- 心跳携带区间字节、区间时长、样本编号及完整性标志。正常情况下每心跳一个区间；确认丢失时保持样本原样重报，收到该平台匹配编号的确认后才推进区间，期间新流量留待下一样本。进程退出不持久保存未确认统计。
- 新增 `kmod-nf-conntrack-netlink` 依赖，在平台建连前启用 `net.netfilter.nf_conntrack_acct`；不修改防火墙或 NAT 规则。计数缺失、事件丢失、容量耗尽或读取失败会标记不完整，当前实现保守地维持该标记至进程重启，页面不将其显示为准确总量。
- 新旧协议字段向后兼容；旧固件不显示虚假的零流量。旧平台不会确认新统计样本，需平台升级后才能推进统计区间，不影响原有业务心跳。
- 本次已通过固件 Windows 主机 Release 17/17、相关源码 MIPS 对象编译，以及构建机临时目录中的 Linux 合成事件测试（平台隔离、确认重试、重连尾部、IPv6、64 位计数）；未修改构建机发布源码目录。
