# EdgeNode 基础 DTU 透传

## 通道模型

平台保存、校验并下发通道配置，EdgeNode 直接连接设备和北向 TCP 服务器。透传字节不经过平台设备采集、协议解析或遥测入库路径。

每个通道包含一个南向端点和一个北向 TCP Client。南向支持串口、TCP Client、TCP Server。TCP Server 接入多个客户端，客户端上行合流到本通道的北向连接；北向下行广播到本通道的所有当前客户端。保留每个客户端内部的字节顺序，不添加客户端标识或消息边界。需要识别设备时，由设备协议本身携带身份。

每节点最多 8 个通道，每通道最多 16 个客户端。不同通道可以连接同一北向服务器，各自持有连接。串口不能与设备采集、手动串口调试或其他透传通道同时占用；同一监听端口不能重复分配。节点在应用完整配置前检查跨平台资源冲突。

## 基础行为

- 通道启停、双向或仅上行、串口参数及空闲组帧间隔。
- 北向断线按 1～30 秒退避重连，TCP keepalive，部分写入处理。
- 注册包和心跳包均支持 ASCII、HEX 输入，各最多 256 字节。格式切换只改变展示；API 配置及线协议最终保存相同字节，不自动追加换行或结束符。ASCII 不接受非 ASCII 字符，任意二进制内容使用 HEX。
- 可选注册包，每次北向连接成功后先发送。
- 可选应用心跳，间隔 1～86400 秒，0 为关闭。注册包发送完成后开始计时，按间隔直接发往北向服务器；不发给南向设备，不进入平台上报心跳。重连重新发送注册包并重新计时，离线期间不累计补发。支持部分写入，发送已排队数据后插入心跳，新到上行数据排在心跳之后，避免持续流量饿死心跳。
- 每个方向或客户端的队列为 4096～65536 字节，默认 32768 字节。上行队列满时停止继续读取；下行慢客户端缓冲不足时断开该客户端。
- 缓冲只存在内存。首次拨号失败时保留尚未发送的上行内容；已建立连接中断时，不保证待发内容重放或业务级可靠交付。
- 每通道独立子进程，所属采集 Worker 监督和回收，异常退出后重启。
- 包含 DTU 的完整配置通过校验后原子保存到 `/etc/edgenode-dtu`，重启恢复；移除最后一个通道时保存空替换快照，防止旧配置复活。快照限 1 MiB，文件权限 0600，数据流不写入闪存。

配置保存和调试开关变更沿用完整配置下发流程，会重新建立节点采集与透传连接。当前版本不提供无连接中断的单项热更新。

## 调试隔离

通道使用自身 `debugEnabled`，不继承设备、链路或平台上报调试开关。副本经专用 `DtuStatus` 消息，落入 `edge_dtu.status`，不写入 `device_data`、采集 `RawPacket` 或设备/链路报文索引。

调试展示南向接收、南向发送、北向接收、北向发送、注册包和心跳包，包含客户端槽位、字节数及 HEX 摘要。每秒最多 8 条，每条最多 256 字节，并记录省略数量。调试通道拥塞不会阻塞透传；展示的是采样副本，不是完整抓包历史。关闭调试后，平台过滤迟到的副本，仅更新运行状态。关闭调试窗口不改变通道的持久化开关。

页面通过 HTTP 查询、保存、删除配置；DTU 状态复用边缘节点页面的一条 SSE，仅更新 DTU 缓存。调试窗口不另建 SSE，未变化状态不重复写入和触发业务事件。

## 协议及存储

新增 `CONFIG_ITEM_DTU = 9`、`ConfigItem.dtu = 18`、`CapabilityReport.supports_dtu = 9` 和 `Envelope.dtu_status = 88`，现有字段编号及 `0.3.44` 下载、配置路径不变。只有声明 DTU 能力的节点允许配置透传。

迁移 `0051` 新建 `edge_dtu`，以节点和通道 UUID 为联合主键，保存配置、编码后的下发内容及独立运行状态。配置提交后下发失败时，接口明确返回已保存但下发失败，可通过同步配置重试。

## 注册包和心跳包补充验证

`tests/edge-dtu-config-test.ts` 验证 ASCII 编码、非 ASCII 拒绝、字节数限制、HEX 校验和心跳开关条件。浏览器验证 `DEV001`、`PING` 的格式切换及配置保存。固件测试验证心跳只发往北向、定时发送、重连后注册优先且重新计时、间隔为 0 时保持停用；主机测试 22/22 通过。HTTP/WS 集成验证心跳字段下发及禁用。协议在 `DtuConfig` 新增字段 16、17，旧配置缺省不发送心跳，无数据库迁移。
